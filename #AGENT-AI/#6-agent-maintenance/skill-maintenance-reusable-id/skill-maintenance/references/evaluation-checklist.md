# Daftar Periksa Evaluasi Skill

## Sebelum memberi rekomendasi
- [ ] Identifikasi skill yang benar-benar menjadi sasaran.
- [ ] Baca instruksi utama dan referensi yang relevan.
- [ ] Gunakan hanya riwayat, umpan balik, dan artefak yang benar-benar tersedia.
- [ ] Pisahkan masalah teramati, preferensi pengguna, dan dugaan.
- [ ] Bedakan aturan reusable dari aturan khusus project.
- [ ] Periksa konflik dengan skill lain dan tujuan aslinya.

## Sebelum menerapkan perubahan
- [ ] Sajikan temuan, alasan, risiko, dan patch yang diusulkan.
- [ ] Dapatkan persetujuan pengguna yang jelas.
- [ ] Batasi perubahan pada file yang disetujui.
- [ ] Jangan memasukkan rahasia atau detail project yang tidak perlu.
- [ ] Pertahankan bahasa Indonesia sebagai default.
- [ ] Jangan mengubah nama skill atau perintah tanpa persetujuan.

## Setelah menerapkan perubahan
- [ ] Periksa struktur dan format file.
- [ ] Pastikan semua referensi yang disebutkan tersedia.
- [ ] Periksa konflik, duplikasi, dan instruksi yang ambigu.
- [ ] Pastikan tidak ada file di luar cakupan yang berubah.
- [ ] Laporkan perubahan dan validasi secara jujur.
